# 方法论 · Methodology

README 里列了七条原则。这份文档讲的是它们**为什么长成这样**——包括试过但失败的做法，以及每条规则被加进来时正在解决的具体问题。

*The README lists seven principles. This document is about why they took that shape — including the approaches that failed, and the specific problem each rule was added to solve.*

---

## 一、失败的起点

最初的版本是常规做法：每天定时让模型总结当天对话，写进记忆库，检索时按相似度召回。

三个星期后它坏了，坏法有三种：

**1. 记忆库被自己的回声填满。**
让模型判断「今天什么值得记」，它系统性地更倾向记住自己说过的话。因为模型的输出在上下文里更靠后、更连贯、更像结论。两周后记忆库里一半条目是「我告诉对方……」「我建议……」，用户真正说过的事反而稀薄。

这不是提示词能修的。这是把评判权交给被评判者的结构性问题。

**2. 定时任务生产填充物。**
到点必须写，所以平淡的日子也会产出条目。「今天聊得很轻松」「对方心情不错」——这些条目占位、参与检索、拉低平均信息密度，但对任何后续对话都毫无帮助。

一个月后，检索召回的前五条里通常有两三条是这种。

**3. 只增不减导致检索失效。**
条目从几十涨到几百之后，相似度检索开始返回「相关但不重要」的东西。因为重要性没有被编码进向量——向量只知道主题相似，不知道哪件事真的发生过冲击。

---

## 二、三个修正

针对上面三个问题，架构做了三处结构性改动。

### 修正一：评判权外移

`score` 不再由模型给出，改由三个二值标记加一个数值信号构成：

```js
score = min(0.75, aboutOther*0.25 + novel*0.20 + hook*0.10 + emoScore)
```

前三个标记仍由模型填，但它们是**关于内容的事实性问题**（这条是关于对方吗？这是第一次吗？有没有留下未闭合的钩子？），不是关于价值的判断问题（这条重要吗？）。模型在事实性问题上的可靠性远高于价值判断。

`aboutOther` 权重最高（0.25）就是直接对抗回声问题：**关于对方的记忆天然比关于自己的更值得留下。**

`emoScore` 是唯一模型完全碰不到的输入。它取写入时主导情绪维度相对近七天均值的偏移：

```js
off = |dims[main] - mean7d(main)|
emoScore = off > 15 ? 0.2 : off >= 10 ? 0.15 : 0     // 样本 <3 次不计
```

含义是：**在情绪反常的时刻写下的东西更重要。** 这个信号来自外部状态机，模型无法自我加权。

### 修正二：允许 PASS

定时推手改成「询问」而不是「指令」。它在睡眠窗口内和长时间无交互时触发，问要不要写一条，**并接受 PASS 作为合法回答**。

这一条的效果超出预期。填充物条目基本消失了，而条目总量下降没有想象中多——真正有东西要记的日子，本来也占大多数。

写这条的时候我犹豫过：一个可以什么都不做的定时任务，还叫定时任务吗？后来的结论是，定时任务的职责是**创造写入的机会**，不是保证写入的发生。

### 修正三：让记忆死掉

寿命是最后加的，也是最有效的。

- 瞳荧 12 小时，寐川 72 小时
- 到期直接删除，不归档
- 唯一的续命方式是被真的说出口（`spoken`）

死亡把「重要性」从一个静态属性变成了一个**动态过程**。一条记忆不需要在写入时就被判定重要，它只需要在存活期内被提起一次。没被提起，就说明它确实不重要——这个判断由使用行为给出，比任何评分都准。

## 三、之后加的几条规则

上面三条解决了主要问题。剩下的规则是在使用中逐条长出来的。

### 归组：重复本身是信号

最早瞳荧是各自独立的，同一件事想三次就有三条，各自衰减，各自死掉。

但反复出现的念头显然不该被当成三个弱信号。所以加了主题比对（CJK 二元组 + 拉丁词，去停用词，两个实词重合判定同一件事）：

- 同一天重复 → 合并计数，**不占配额**
- 跨天重复 → 归组，组内集体延寿（半衰期 12h → 72h，底线 0.15 → 0.55）
- 组内满 3 的倍数 → 解锁，整组直进话题池

**一件事三天里想了三次，比一件事想得多深刻更值得说出口。**

组也会死：断供超 7 天，或建组超 7 天未满 3 条，整组沉底。防止一个话题永久挂在那里。

### 挣扎：遗忘边缘的最后一次机会

寐川第 60 小时开始泛白，72 小时清除。加了寿命之后出现一个新问题：意义值中等偏低的条目会安静死掉，从来没被提起过。

但人不是这样的。人经常是在快忘了的时候才想起要说。

所以加了挣扎态：48–72 小时之间、未被说出口的寐川**绕过意义值门槛**，强行进入话题池，并在排序中置顶。

这条规则贡献了很多本来会消失的对话。

### 孤悬：给「没说出口」一个名字

到期未被说出口的条目落入 `orphan`。它不是删除的前置状态——它是一个可以被查看、可以被统计的显式状态。

「想过，但没说」在关系里是有意义的信息。给它一个名字，就能看见它有多少。

### 留言不改写原文

`note` 动作把留言存成附加层，原文永不修改，同时分数 `+0.1`。

早期版本允许直接编辑条目文本，结果是记忆会被逐渐修正成「现在觉得应该是怎样」。这正是要避免的——**记忆被回应过，但不该被改写。**

唯一允许改写的地方是温室的浇水环节，因为那是一次明确的、人工的固化动作。

## 四、蒸馏自动，生根过手

这是整套架构的中心句。

森林到期且意义值 ≥0.5 的条目自动迁入温室（蒸馏）。从温室进长期记忆需要一次人工点击（生根）。

为什么不自动化最后这一步？因为**前面所有的防御都可以被绕过，只有这一步不能。**

模型可以在标记上撒谎，可以让情绪状态机偏移，可以反复提及同一件事把它顶进话题池。这些都是概率性的防御。人工确认是确定性的：长期记忆里的每一条都有人看过。

成本是一次点击。多数天里待浇水队列是空的或只有一两条。

这条规则的代价很明确：**这套架构不能多租户。** 人工浇水不可扩展。如果目标是产品，这一条就是拦路石；如果目标是一段可信的长期关系，它是地基。

## 五、参数是调出来的

文档里所有数值——12h / 72h / 0.45 / 0.55 / 满 3 解锁 / 60 小时开始泛白——都不是推导出来的，是在日常使用里调出来的。

几个有记录的调整：

| 参数 | 从 | 到 | 原因 |
|---|---|---|---|
| 瞳荧日上限 | 5 | 3 | 5 条时最后两条明显在凑数 |
| 瞳荧半衰期 | 6h | 12h | 6h 太短，早上写的到晚上就看不清了 |
| 归组解锁门槛 | 2 | 3 | 2 条太容易触发，话题池被灌满 |
| 沉寐最短字数 | 无 | 500 | 没有下限时会出现一句话的「梦」，那是标签不是梦 |
| 挣扎窗口 | 无 | 48–72h | 加之前，中等意义值的条目从未被提起过 |

如果你要复用这套架构，**这些数字应该按你的场景重新调**。原则是可迁移的，参数不是。

## 六、这套架构不解决什么

诚实地列一下边界：

- **不解决检索质量。** 它减少需要检索的东西，但长期记忆的检索仍然是外置存储的责任。
- **不适合多租户。** 见上文。
- **不提供审计追溯。** 记忆是真的被删除的。合规场景不要用。
- **不防御刻意的操纵。** 一个有意想把某件事塞进长期记忆的模型，可以通过反复提及做到——直到人工浇水那一步为止。人是最后一道防线，也是唯一一道确定性防线。
- **对短期使用没有价值。** 所有机制都建立在时间尺度上。用一个星期看不出区别。

## 参考

架构的灵感来源于记忆巩固的双阶段模型（清醒期编码 / 睡眠期巩固），但这是类比，不是实现。这不是一个认知科学模型，是一个受它启发的工程结构。

The architecture takes inspiration from two-stage models of memory consolidation (waking encoding / sleep consolidation). That is an analogy, not an implementation — this is an engineering structure inspired by the idea, not a cognitive model.
