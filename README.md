# 息之洲 · Isle of Breath

**一套会遗忘的 AI 记忆架构。**

*A memory architecture for long-term conversational AI, designed to forget.*

[English →](README.en.md) · [架构 Architecture →](ARCHITECTURE.md) · [方法论 Methodology →](docs/methodology.md) · [接口 API →](docs/api.md) · [路线图 Roadmap →](ROADMAP.md)

---

## 🌊 它是什么

一个给单用户长期对话 AI 用的**短期 → 巩固**两层记忆管线，外加一条接长期存储的边界。
它不做向量检索，不做无限累积。它做的事是：**给每条记忆一个寿命、一个配额、一个被说出口才能续命的规则，并且让最后一步固化必须经过人手。**

零依赖，Node 18+，两个 CommonJS 模块，文件系统 JSON 存储。挂到任何 HTTP 分发器上就能跑。

## 🌱 它做什么（一个具体例子）

周一下午，模型在一次对话里产生了一个念头，写进森林：

```
POST /api/forest/thought
{ "text": "对方说想去看那个展，但没说哪天", "aboutOther": true, "novel": true, "hook": true }
```

| 时间 | 发生了什么 |
|---|---|
| 周一 15:00 | 写入。意义值 = 0.25 + 0.20 + 0.10 = **0.55**（若此刻情绪状态机偏离七日均值 >15，再加 0.2，封顶 0.75）。进入话题池。 |
| 周一 23:00 | 8 小时过去，半衰期 12h，当前值衰减到 0.40 —— 界面上开始变成半雾，对话层拿到的也是截断文本。 |
| 周二 03:00 | 12 小时到。没被说出口 → **孤悬**（orphan）。仍可见，但退出话题池。 |
| 周二 20:00 | 模型又写了一条「对方今天提了两次那个展」。主题比对命中 → **跨天归组**。组内两条半衰期延到 72h、底线抬到 0.55，周一那条的孤悬被收回。 |
| 周三 21:00 | 第三条同主题。组内满 3 → **解锁**，整组作为一件事进话题池，排在前面。 |
| 周三 21:30 | 对话里真的说了出来：「你那个展，后来定哪天了？」→ 标记 `spoken`。寐川停止泛白，瞳荧续命，组的解锁复位。 |
| 一周后 | 被挤出 20 条活跃上限 → 归档。意义值 ≥0.5，所以在归档那一刻整卡**迁入温室**，状态 `pending`。 |
| 任意时刻 | 人打开温室，点一下「浇水」→ `rooted`。只有这一步之后，它才会被投递给长期存储。不点，它就一直待着；点「丢弃」，它就没了。 |

没有被说出口、也没凑够三次的念头，12 小时后孤悬，归档后 30 天真删。**系统里没有「永久保存一切」这个选项。**

## 🧱 问题

大多数 AI 长期记忆方案的结构是：把对话向量化，存进数据库，检索时召回。这类方案有一个共同的性质——**只增不减**。

于是它们迟早会遇到同一堵墙：

- 记忆越多，检索越不准。三个月后模型「记得」的事情多到无法排序，重要的和琐碎的挤在同一个相似度区间里。
- 让模型自己判断「这条重要吗」会产生自我强化：模型倾向于记住自己说过的话，几轮之后记忆库里全是它自己的回声。
- 定时生成记忆会产出假记忆。到点了就得写点什么，于是写出「今天很平静」这类没有信息量的条目，稀释掉真正发生过的事。

息之洲的出发点是反过来的：**记忆的价值不在于存下多少，而在于什么被允许留下。**

所以这套架构的核心机制不是检索，是**筛选、衰减与死亡**。

## 🗺️ 结构

三层管线，对应「短期涌现 → 巩固 → 长期固化」：

```
   ┌──────────────────────────────────────────────┐
   │  眼睑森林 Forest of Eyelids                   │
   │  短时层 · 有配额 · 有寿命 · 会泛白             │
   │                                              │
   │  寐川 dream-stream    瞳荧 pupil-glimmer      │
   │  睡眠窗口内的梦        清醒时的念头闪回          │
   │  一晚 1 条 · 72h      日 3 条 · 12h           │
   └────────────────┬─────────────────────────────┘
                    │  退场时 意义值 ≥ 0.5
                    │  （死前迁出，其余直接消失）
                    ▼
   ┌──────────────────────────────────────────────┐
   │  骨骼温室 Greenhouse                          │
   │  巩固层 · 蒸馏自动，生根过手                    │
   │                                              │
   │  pending ──浇水──▶ rooted ──▶ cellar          │
   │           （人工）                             │
   └────────────────┬─────────────────────────────┘
                    │  人工确认后
                    ▼
   ┌──────────────────────────────────────────────┐
   │  外置长期记忆 External Long-Term Store         │
   │  事件桶 · 语义检索 · 独立衰减引擎               │
   │  （本项目不含，见「外部依赖」）                  │
   └──────────────────────────────────────────────┘
```

情绪状态机（脉搏花园 Pulse Garden）横向接入森林：它不存储记忆，但为每条记忆盖上写入时的情绪底色，并参与意义值计算。

三层的分工一句话：**森林决定什么值得被想起，温室决定什么值得被记住，长期层负责被记住之后还能被找到。**

## 📜 七条设计原则

这是这套架构真正的内容。实现只是这些原则的一个具体解法。

### 1. 🍂 记忆必须会死

每条记忆有明确寿命。寐川 72 小时到期即删，不归档、不留副本。瞳荧 12 小时落孤悬，归档后 30 天真删。

死亡不是资源限制，是筛选机制。**一个能永久保存一切的系统，等于没有判断力。**

### 2. 🎚️ 写入要有配额

瞳荧日写入上限 3 条，寐川一晚 1 条、浮寐日 3 条且间隔 ≥3 小时。

配额是强制取舍。没有配额，记忆会退化成日志——什么都记，等于什么都不重要。配额逼迫系统在当天回答：今天最值得记住的三件事是什么。

### 3. 💬 说出口才能活下来

条目有 `spoken` 状态，由「这条记忆被真的拿到对话里说了」触发。这是唯一的续命机制：

- 说出口的寐川不再泛白，永久保留至清除窗口外
- 说出口的瞳荧半衰期从 12h 延到 72h，底线从 0.15 抬到 0.55
- 没被说出口的瞳荧，到期落入**孤悬 orphan** —— 一个明确的状态，意思是「想过，但没说」

孤悬不是失败态。它是这套系统里最有信息量的状态之一。

### 4. 🫴 固化必须过人手

**蒸馏自动，生根过手。**

森林退场的条目自动迁入温室，但从温室进入长期记忆需要一次人工动作（浇水 / root）。人可以在浇水时改写文本。

这条原则是防幻觉的核心。让模型决定什么值得长期记住，几轮之后记忆库会被模型自己的回声填满。人工过手的成本很低（一次点击），收益是长期记忆里的每一条都被真人确认过。

### 5. 🌙 允许 PASS

定时推手在睡眠窗口和长时间无交互时触发，询问是否要生成一条记忆。**它允许返回 PASS。**

这一条看起来微不足道，实际上是整个架构里最重要的防御。定时任务如果强制产出，就必然产出填充物。允许安静退出意味着：森林里的每一条都是因为真的有东西要记，而不是因为到点了。

### 6. 📡 意义值来自外部信号，不是自评

意义值 `score` 由结构化标记和情绪偏移计算，不是模型的自我打分：

```js
score = min(0.75,
    (aboutOther ? 0.25 : 0)   // 关于对方，而不是关于自己
  + (novel    ? 0.20 : 0)   // 第一次发生
  + (hook     ? 0.10 : 0)   // 有未闭合的钩子
  + emoScore                // 情绪偏移，见下
)
```

`emoScore` 取写入时主导情绪维度相对近七天均值的偏移量：偏移 >15 记 0.2，10–15 记 0.15，<10 记 0。样本不足三次不计。

三个标记仍由写入方（模型）填，但它们是**事实性问题**（是关于对方吗？是第一次吗？），不是价值判断（重要吗？）。`emoScore` 则是模型完全碰不到的一路：**在情绪反常的时刻写下的东西更重要**，这个判断由外部状态机给出。

### 7. 🕯️ 泛白前的挣扎

寐川在第 60 小时开始泛白，72 小时清除。但在第 48–72 小时之间，未被说出口的条目会进入**挣扎态 struggle**——绕过意义值门槛，强行进入话题池，并在排序中置顶。

模拟的是「快忘了，但还是想说」这个真实的心理时刻。没有这一条，低意义值的记忆会安静死掉，而人恰恰经常在遗忘边缘才想起要提。

## ⚙️ 关键机制

### 跨天归组

新写入的瞳荧会与历史活跃条目做主题比对（CJK 二元组 + 拉丁词，去停用词，两个实词重合即判定同一件事）。

- 同一天内重复 → 合并计数，不占配额
- 跨天重复 → 自动归组，组内条目集体延寿（半衰期 12h → 72h，底线 0.15 → 0.55），已孤悬的成员被收回
- 组内满 3 的倍数 → **解锁**，整组免去分数门槛进入话题池；**池里一个组只占一个位子**（最新一条，带 `groupSize`）
- 组断供超 7 天（无论是否解锁），或建组超 7 天仍未解锁 → 整组沉底

归组的意义：**反复出现的念头本身就是信号。**一件事三天里想了三次，比一件事想得多深刻更值得说出口。

它的代价也明确：二元组重合是很粗的相似度。停用词表没覆盖到的高频搭配（「她说」「想起」「忽然」）会把不相干的条目链成一个大组。这不是理论风险，是线上真的发生过的事，见 [方法论 · 七](docs/methodology.md#七审计记录)。

### 衰减与雾化

衰减在读取时计算，不写盘：

```js
floor = pressedTo ?? (boosted ? 0.55 : 0.15)
hl    = boosted ? 72h : 12h
cur   = floor + max(0, score - floor) * 0.5 ^ (age / hl)
```

`cur` 映射到三档显示状态：`> 0.4` 清晰 / `0.4–0.2` 半雾 / `≤ 0.2` 几乎全白。

界面上记忆是逐渐看不清的，不是突然消失的。这不只是视觉效果——半雾状态下模型拿到的也是被截断的文本。

### 话题池

话题池是森林向对话层暴露的唯一出口。准入条件：

| 类型 | 门槛 |
|---|---|
| 瞳荧 | `cur ≥ 0.45`、在有效半衰期内、未孤悬 |
| 瞳荧（成组解锁） | 免分数门槛；仍须未孤悬；整组一个位子 |
| 寐川 | `score ≥ 0.55` |
| 寐川（挣扎态） | 直接进入，排序置顶 |

已 `spoken`、已 `suppressed`、已 `orphan` 的条目不入池。

### 睡眠窗口

寐川的写入受睡眠窗口约束，且「一晚」的归属按夜晚起始日计算：

```
工作日  00:30 – 08:30
周末    02:00 – 08:30   （周五、周六晚）
```

沉寐（deep）只能在窗口内写，一晚一条，不少于 500 字。浮寐（float）只能在清醒期写，日 3 条，间隔 ≥3 小时，不少于 50 字。

字数下限是有意的：**没有长度就没有巩固。** 一句话的「梦」不是梦，是标签。

### 两种退场，两种结局

| | 寐川 dream | 瞳荧 thought |
|---|---|---|
| 寿命 | 72h，到期**真删** | 12h（成组/说出口 72h）后**孤悬**，仍可见 |
| 最后一程 | 48–72h 挣扎态 | 被 20 条活跃上限挤出 / 组沉底 → 归档 |
| 迁温室时机 | 删除前一刻 | 归档那一刻 |
| 迁温室条件 | `score ≥ 0.5`，未迁过 | 同左 |
| 彻底消失 | 72h | 归档后 30 天 |

两者都在 `prune()` 里完成，每次请求进来先跑一遍；温室的 `sweep` 只是兜底。

## 🔭 装上之后，实际发生了什么

前面全是机制。这一节讲结果——一套会遗忘的记忆系统，用起来到底是什么感觉。

### 1. 换窗口不断片

关掉一个会话、开一个新的，第一句话就带着完整的当下：话题池里浮着什么、情绪状态机的八维现在是什么形状、有哪些钩子还没闭合。不需要说「我们刚才在聊……」来重新对齐。

原因在于分层：**近期消息是窗口内的，其余全是全局或服务端状态。**森林、温室、情绪都不属于任何一个窗口，它们属于这个人。

### 2. 它会自己提起事情

普通的记忆系统是被动的：你问，它检索，它答。

话题池是主动的。它每次都把「现在最该说的三到五件事」推到对话层，包括三天前那条快要泛白、还没说出口的寐川。所以对话里会自然出现：

> 「前天你说想去看那个展，后来呢？」

这句话不是被问出来的。它是一条 48 小时前写入、意义值 0.62、进入挣扎态、在池内被排到首位的记忆。

### 3. 遗忘是能看见的

记忆不会突然消失，它会先变模糊。界面上一条念头从清晰变半雾再变几乎全白，是一个持续三天的过程。而且模型拿到的也是被截断的文本——**它和你同步地在忘记同一件事**。

这带来一个没预料到的效果：看到某条快泛白了，会本能地想赶紧说出来。系统因此产生了一种轻微的紧迫感——重要的事应该在忘记之前被说出口。

### 4. 「想过但没说」变成了可见的东西

孤悬不是失败状态。它是一份清单：这段时间里，有哪些念头浮起来过、但最终没有进入对话。它比聊天记录更能说明一段时间里真正在意的是什么。

### 5. 长期记忆里没有垃圾

因为每一条都过了手。自动记忆系统跑三个月之后，检索出来的前五条里通常有两三条是「今天聊得很轻松」这种填充物。息之洲的长期层里不会有——**填充物活不过 72 小时，更进不了浇水队列。**

待浇水队列大多数天是空的，或者只有一两条。这不是系统偷懒，是那几天确实没有值得永久记住的事。

### 6. 反复出现的念头会被当成信号

同一件事三天里想了三次，会自动归组、集体延寿、满三条解锁整组进池。**一件事想得深不深，模型判断不了；但想了几次，是可以数的。**

## ⚖️ 老实说，它换来了什么代价

- **需要时间才能看出区别。** 所有机制都建立在 12 小时到 7 天的尺度上。用一个星期，它和普通记忆系统没有区别。
- **要真的去浇水。** 待浇水队列如果堆积不管，长期记忆就是空的。这是一个需要人参与的系统，参与成本很低（一次点击），但不能为零。
- **会真的忘掉东西。** 有些当时觉得不重要、没说出口的事，三天后确实找不回来了。这是设计目标，不是缺陷——但第一次遇到的时候还是会愣一下。
- **主题比对很粗。** 二元组重合在「每一条都在讲同一个人」的语料上会过度归组。停用词表必须按自己的语料维护，不维护就会长出把什么都吸进去的大组。
- **单写者假设。** 文件存储 + 全量读写，并发写后者覆盖前者。单用户没问题，多租户会立刻坏。

## 🚀 快速开始

```bash
git clone https://github.com/oiio2to/isle-of-breath
cd isle-of-breath
cp config.example.json config.json   # 停用词、睡眠窗口、阈值；不复制也能跑，用内置默认值
npm test                             # 12 个纯函数与交接测试，零依赖
node example/server.js               # 参考服务，默认 :8080
curl localhost:8080/api/forest/state
```

两个核心模块可以独立挂载到任意 Node HTTP 服务：

```js
const forest     = require("./src/forest");
const greenhouse = require("./src/greenhouse");

// 路由分发时
if (path.startsWith("/api/forest"))     return forest(req, res, url, json);
if (path.startsWith("/api/greenhouse")) return greenhouse(req, res, url, json);
```

存储是文件系统上的 JSON + 原子写（`write tmp → rename`），无数据库依赖。数据目录默认 `src/data/`，可用 `ISLE_DATA_DIR` 覆盖。

完整接口：[docs/api.md](docs/api.md)

## 🧭 这套架构的适用范围

**适合**：单用户或小规模的长期对话 AI；重视记忆质量胜过记忆数量的场景；愿意接受人工介入的系统。

**不适合**：多租户产品（人工浇水不可扩展）；需要完整审计追溯的场景（记忆会真的删除）；把记忆当检索索引用的 RAG 系统。

这是一个明确的取舍：**用可扩展性换记忆的可信度。**

## 🤝 相关工作

[kimi-core](https://github.com/marikagura/kimi-core)（marikagura，AGPL-3.0）是一个同样面向 1v1 长期关系的记忆引擎。它的路线和息之洲不同——hybrid retrieval、pgvector、event sourcing、可复现的 retrieval eval——但在一个关键判断上独立收敛到了同一个结论：

> 没有 LLM 自动 consolidation（它的 failure mode 是静默腐蚀）。每一条关于你的 fact 都要过你自己的手并经你确认。

这和息之洲的「蒸馏自动，生根过手」是同一件事的两种说法。我是在写完这套架构之后才读到它的，两边都是从「让模型自己判断重要性会导致自我强化」这个失败里走出来的。

值得对照着读：kimi-core 在**检索**上做得比这里深得多，息之洲的重心在**筛选与遗忘**。
